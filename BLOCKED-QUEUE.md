# Cascade rules (v4)

Only gems touching the actual floor can be consumed. All 30 canonical boards retain six colors and 6–8 initial floor gems. Levels 1–5 have three shelf spaces; later levels have two. A selected bottle occupies its slot until full.

Queue branches unlock when their parent bottles FINISH, including both parents at a join. Taking a parent does not unlock a child. Immediate blocked recipes are visible for planning; deeper tiles use identical blank rectangles. A brewing marker retains the occupied parent's place in the queue.

A draw starts one simultaneous stream per matching idle bottle. Physics settles after removals before scheduling the next draw; active streams do not block other bottles. Choosing a bottle starts a new cascade. Consecutive draw waves without another choice raise the multiplier; parallel draws add to it, capped at ×8. Thinking time never resets a cascade. Points are awarded at reservation, and each bottle retains its highest earned multiplier for the clear bonus, so choosing another flask during a pour cannot erase that bottle's bonus.

Levels 11–15 introduce ordered ingredient recipes. The leftmost unconsumed band is the next ingredient. Levels 16–30 also contain heavy crystals (diamond emblem): over twice the mass, higher friction, lower bounce. Recipes are generated by replaying actual floor removals, preserving the exact inventory. Every board has a checked winning route; queue variants are filtered with random-play probes. Wide gem shapes already provide physical bridges; fragile splitting ingredients are not included in this iteration.

Medals are saved on this device per level. Gold requires a cascade at least as long as that board's largest bottle; silver is one multiplier lower (minimum ×2). Undo or shake makes the run practice and caps its medal at bronze.

Daily chooses one canonical level from 6–30 using the UTC date. Everyone receives the same board. Daily rankings use a date-specific ruleset, separate from journey rankings. They rotate at 00:00 UTC; the 25-board daily selection repeats after 25 days. This is a daily competition, not a promise of a newly generated board every day.

The server verifies completed-parent locks, ordered ingredients, distinct reservations, bottle ownership, finishes and deterministic scores. New scores use cascade-v4; old records remain stored under their prior rulesets. Existing pre-update tickets must restart. The physical replay retains equivalent-color tolerance for contact-order drift; this is a casual leaderboard, not an anti-bot system.

Liquid uses a bounded, fixed-step 2D position-based particle simulation with gravity, density relaxation and viscosity. Three.js reconstructs a smooth density surface and shades its normals; simulation particles are not exposed as visible spheres. Bottle interiors use a damped wave surface, impacted by arriving volume and bottle tilt. This is a lightweight 2D fluid approximation, not a full 3D Navier–Stokes solver. Concurrent jets have independent simulations, a spatial neighbor grid, and a shared render buffer. Rendering stops when the board, bottles and fluid settle. WebGL loss retains the Canvas fallback.

Checks: node verify-blocked.mjs, node verify-cascades.mjs, node verify-liquid.mjs, node verify-vercel-proxy.mjs. With the local Worker on port 4174: node verify-api.mjs. Build native Vercel output with npm run build:vercel, or Worker output with npm run build. Regenerate boards explicitly with node scripts/block-catalog.mjs; builds only copy the checked catalog.
