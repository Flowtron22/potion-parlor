# Brewing rules (v6)

Only gems touching the actual floor can be consumed. All 30 canonical boards retain 6–8 initial floor gems. Colors increase from three to six, and levels 1–16 have three shelf spaces; later levels have two. A selected bottle occupies its slot until full.

Queue branches unlock when their parent bottles FINISH, including both parents at a join. Taking a parent does not unlock a child. Immediate blocked recipes are visible for planning; deeper tiles use identical blank rectangles. A brewing marker retains the occupied parent's place in the queue.

A draw starts one simultaneous stream per matching idle bottle. Physics settles after removals before scheduling the next draw; active streams do not block other bottles. Choosing a bottle starts a new cascade. Consecutive draw waves without another choice raise the multiplier; parallel draws add to it, capped at ×8. Thinking time never resets a cascade. Points are awarded at reservation, and each bottle retains its highest earned multiplier for the clear bonus, so choosing another flask during a pour cannot erase that bottle's bonus.

Levels 13–16 introduce ordered ingredient recipes. The leftmost unconsumed band is the next ingredient. Levels 23–30 also contain heavy crystals (diamond emblem): over twice the mass, higher friction, lower bounce. Recipes are generated by replaying actual floor removals, preserving the exact inventory. Every board has a checked winning route; queue variants are filtered with random-play probes. Wide gem shapes already provide physical bridges; fragile splitting ingredients are not included in this iteration.

Medals are saved on this device per level. Gold requires a cascade at least as long as that board's largest bottle; silver is one multiplier lower (minimum ×2). Undo or shake makes the run practice and caps its medal at bronze.

Daily starts on one canonical level from 6–30 using the UTC date. Everyone receives the same starting board and continues through the same level sequence. Daily rankings use a date-specific ruleset, separate from journey rankings. They rotate at 00:00 UTC; the 25-board daily selection repeats after 25 days. This is a daily competition, not a promise of a newly generated board every day.

The server verifies completed-parent locks, ordered ingredients, distinct reservations, bottle ownership, finishes and deterministic scores. New scores use survival-v6; old records remain stored under their prior rulesets. Existing pre-update tickets must restart. The physical replay retains equivalent-color tolerance for contact-order drift; this is a casual leaderboard, not an anti-bot system.

Liquid now uses Pavel Dobryakov's MIT-licensed WebGL Fluid Simulation solver, adapted to Three.js render targets. GPU passes advect velocity and dye, compute curl/vorticity, solve pressure with 14 Jacobi iterations, and subtract the pressure gradient. A controlled inlet directs each simultaneous pour; masked fields inside the actual SVG flask silhouettes advect and mix the arriving pigments. The previous CPU particle jet and its reconstructed particle surface have been removed. The SVG fill boundary retains its damped wave response. Like the reference, this is a 2D velocity/dye simulation, not a 3D free-surface water solver. Solver fields are pooled for pours, disposed when bottles leave, prewarmed at startup, and paused after settling. The browser profile reports fluidEngine=pavel-dobryakov. See FLUID.md and public/play/vendor/pavel-fluid/LICENSE for provenance and license. WebGL loss retains the Canvas fallback.

Checks: node verify-blocked.mjs, node verify-cascades.mjs, node verify-liquid.mjs, node verify-vercel-proxy.mjs. With the local Worker on port 4174: node verify-api.mjs. Build native Vercel output with npm run build:vercel, or Worker output with npm run build. Regenerate boards explicitly with node scripts/block-catalog.mjs; builds only copy the checked catalog.

## Gradual difficulty (survival-v6)

The reproducible `node scripts/block-catalog.mjs` builder derives every flask ingredient from an actual floor-contact removal route. Canonical client/server catalogs stay identical. Only 6–8 large floor gems can pour; upper gems still have to fall.

- Levels 1–4: three colors, three shelf slots, three opening flask choices, short single-color bottles and single-parent locks.
- Levels 5–8: four colors and three slots; branch choice matters more.
- Levels 9–12: five colors, three slots, two opening branches and some two-parent locks. No ordered recipes yet.
- Levels 13–16: six colors, three slots, ordered recipes mixed into the queue and tighter branch priorities.
- Levels 17–22: two slots and more ordered recipes.
- Levels 23–30: more mixed recipes and heavy gems.

Queue selection targets a difficulty band instead of minimizing random-play wins. Independent holdout probes on levels 1/4, 8/12, and 13/16/20/30 produced 92%, 79%, and 25% random-play clears respectively. These are automated blind-play probes, not player success estimates. Every canonical board and shuffled restart retains a verified winning route. The scoring ruleset changes to v6 so old layout tickets cannot verify against the new catalog.
